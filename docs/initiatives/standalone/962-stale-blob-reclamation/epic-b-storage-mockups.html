Storage card and clear confirmation (Epic B, #966)

Material 3, light scheme, blue seed, as main.dart configures it. Dark follows the same tokens and is not drawn. Phone pane at 360 wide, the narrowest real target; the Windows pane is the same widget in a wider column. Numbers are the owner's actual install on 2026-10-22: 70.9 MB database, 47 migrated keys, 40 with a stale copy, 29,975 messages, about 16.6 MB reclaimable. Bullets under each card are the behaviour to build. Owner-approved 2026-10-23: all variants as drawn, and the label stays Clear Stale History Now rather than "Compact" — his reason is that the name generalises, so the same action can later cover clearing stale history for other reasons, such as the retention limit in #963. Variants 1 to 10 are built; 11 is the rejected label alternative, kept for the record.

Proposed: confirm before deleting

None of this exists. It needs a preview pass in the sweep: verify every eligible key and total it, without deleting, so the dialog can state real numbers rather than a guess. The verification then runs twice, once to preview and once under the key lock to delete, which is the cost of saying what will go before it goes.

8Confirm, the normal case

States what will be cleared, what is not affected, and that it cannot be undone. The action button carries the count so the last thing read is the scope.

  • Counts come from a real preview pass, not an estimate.
  • Cancel is the plain text button and sits left, so the destructive one is never the default target.
  • Dismissing by tapping outside or back cancels.
